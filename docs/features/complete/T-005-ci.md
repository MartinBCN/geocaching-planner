# T-005: Continuous integration

- **Status:** Complete
- **Milestone:** M0
- **Depends on:** T-003, T-004
- **Requirements:** NFR-8
- **Related ADRs:** ADR-0008
- **Reviews:** [Council review 1](../../reviews/features/T-005-ci-review-1.md)

## Goal
Every pull request and push to `main` runs the backend and frontend quality gates plus pre-commit on GitHub Actions. Playwright E2E remains a local test and does not run on GitHub-hosted runners.

## Context
ADR-0008 defines the GitHub CI checks; ADR-0007 requires project commands to run through mise. The generated OpenAPI client must stay synchronized (ADR-0005). This private, undeployed project keeps E2E available locally without spending hosted runner time on it.

## Scope
### In
- `.github/workflows/ci.yml` is triggered on `pull_request`, `push` to `main`, and `workflow_dispatch`. It uses `jdx/mise-action` so tool versions match `mise.toml`; workflow permissions are `contents: read`, third-party actions are pinned to commit SHAs.
  - Jobs `backend` and `frontend` run `mise run check:backend` and `mise run check:frontend` respectively. They upload coverage artifacts.
  - Required job `pre-commit` runs `mise run check:pre-commit`, which runs all pinned hooks including gitleaks. CI sets `SKIP=mypy` because strict mypy runs in `check:backend`.
  - Playwright remains available locally through `mise run test:e2e`; GitHub Actions does not run E2E.
- Caching for uv and pnpm.
- `concurrency` group cancels superseded pull-request runs but never cancels `main` push runs.
- Add a CI badge to the README.

### Out
- Configuring branch protection or a GitHub ruleset. Document the required status-check names (`backend`, `frontend`, `pre-commit`) in a README Development / CI section below Quickstart.

## Acceptance criteria
- [ ] AC1: Given an introduced ruff `F401` in backend source or Biome `noUnusedVariables` in frontend source, when CI runs, then the corresponding `backend` or `frontend` job fails.
- [ ] AC2: Given backend coverage below 85% or frontend coverage below 80%, when CI runs, then the matching job fails at its coverage gate.
- [x] AC3: Given all CI checks pass, when the workflow completes, then `backend`, `frontend`, and `pre-commit` succeed and each job has `timeout-minutes <= 20`.
- [x] AC4: Given `ci.yml`, when workflow tests inspect it, then it contains no setup-python/setup-node/astral-uv/pnpm setup actions or tool version inputs; tool versions come from mise.
- [x] AC5: Given generated client schema is stale, when `check:frontend` runs `api:check`, then it compares a temporary generated schema with `frontend/src/api/schema.d.ts` and reports a clear drift failure without modifying other files.
- [x] AC6: Given the README development section, when the required checks are read, then all three required job IDs (`backend`, `frontend`, `pre-commit`) are listed and E2E is identified as local-only.
- [x] AC7: Given the CI workflow, when a unit test parses it, then its triggers, job IDs, concurrency policy, least-privilege permissions, and mise task-only gate invocations match the stated contract.
- [ ] AC8: Given a pull request, push to main, or workflow dispatch, when the workflow is triggered, then the matching run is available; only superseded PR runs are cancelled.

## Implementation notes
- Every gate step in workflow YAML invokes a mise task, including `check:pre-commit`; no raw formatter, linter, type checker, test runner, or browser runner commands appear in the workflow.
- Pre-commit is a required status check; mypy is skipped only in that hook job because the backend gate runs it.
- Add actionlint as a pinned pre-commit hook. `backend/tests/unit/test_ci_workflow.py` parses the workflow and checks task-only execution, job IDs, triggers, concurrency, permissions, the local-only E2E task, and the README check names.
- Place the badge and required status checks below Quickstart under `Development / CI`; derive the badge repository from `git remote get-url origin`.
