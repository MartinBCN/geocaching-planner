# T-005: Continuous integration

- **Status:** Ready
- **Milestone:** M0
- **Depends on:** T-003, T-004
- **Requirements:** NFR-8
- **Related ADRs:** ADR-0008
- **Reviews:** [Council review 1](../../reviews/features/T-005-ci-review-1.md)

## Goal
Every pull request and push to `main` runs the same quality gates as `mise run check`, plus the e2e smoke test, on GitHub Actions.

## Context
ADR-0008 requires CI and local checks to share a definition; ADR-0007 requires project commands to run through mise. The generated OpenAPI client must stay synchronized (ADR-0005).

## Scope
### In
- `.github/workflows/ci.yml` is triggered on `pull_request`, `push` to `main`, and `workflow_dispatch`. It uses `jdx/mise-action` so tool versions match `mise.toml`; workflow permissions are `contents: read`, third-party actions are pinned to commit SHAs.
  - Jobs `backend`, `frontend`, and `e2e` run `mise run check:backend`, `mise run check:frontend`, and `mise run test:e2e:ci` respectively. They use Docker only where required and upload coverage/report artifacts.
  - Required job `pre-commit` runs `mise run check:pre-commit`, which runs all pinned hooks including gitleaks. CI sets `SKIP=mypy` because strict mypy runs in `check:backend`.
  - `test:e2e:ci` starts only Compose `db`, migrates, starts the backend on `127.0.0.1:8000`, builds the frontend, starts preview on port 5173, and runs Playwright with `E2E_BASE_URL` defaulting to `http://localhost:5173`. The smoke assertion checks backend health and does not require BRouter. T-015/T-017 own future route smoke coverage.
- Caching for uv, pnpm, and Playwright browsers.
- `concurrency` group cancels superseded pull-request runs but never cancels `main` push runs.
- Add a CI badge to the README.

### Out
- Configuring branch protection or a GitHub ruleset. Document the required status-check names (`backend`, `frontend`, `e2e`, `pre-commit`) in a README Development / CI section below Quickstart.

## Acceptance criteria
- [ ] AC1: Given an introduced ruff `F401` in backend source or Biome `noUnusedVariables` in frontend source, when CI runs, then the corresponding `backend` or `frontend` job fails.
- [ ] AC2: Given backend coverage below 85% or frontend coverage below 80%, when CI runs, then the matching job fails at its coverage gate.
- [ ] AC3: Given all checks pass, when CI completes, then `backend`, `frontend`, `e2e`, and `pre-commit` succeed and each job has `timeout-minutes <= 20`.
- [ ] AC4: Given `ci.yml`, when workflow tests inspect it, then it contains no setup-python/setup-node/astral-uv/pnpm setup actions or tool version inputs; tool versions come from mise.
- [ ] AC5: Given generated client schema is stale, when `check:frontend` runs `mise run api:gen`, then only a change to `frontend/src/api/schema.d.ts` causes a clear drift failure.
- [ ] AC6: Given the README development section, when the required checks are read, then all four required job IDs (`backend`, `frontend`, `e2e`, `pre-commit`) are listed.
- [ ] AC7: Given the CI workflow, when a unit test parses it, then its triggers, job IDs, concurrency policy, least-privilege permissions, and mise task-only gate invocations match the stated contract.
- [ ] AC8: Given a pull request, push to main, or workflow dispatch, when the workflow is triggered, then the matching run is available; only superseded PR runs are cancelled.

## Implementation notes
- Every gate step in workflow YAML invokes a mise task, including `check:pre-commit`; no raw formatter, linter, type checker, test runner, or browser runner commands appear in the workflow.
- `test:e2e:ci` owns the DB-only test stack and configured ports; it does not require BRouter. Pre-commit is a required status check; mypy is skipped only in that hook job because the backend gate runs it.
- Add actionlint as a pinned pre-commit hook. `backend/tests/unit/test_ci_workflow.py` parses the workflow and checks task-only execution, job IDs, triggers, concurrency, permissions, and the README check names.
- Place the badge and required status checks below Quickstart under `Development / CI`; derive the badge repository from `git remote get-url origin`.
